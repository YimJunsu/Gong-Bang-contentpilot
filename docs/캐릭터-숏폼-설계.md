# 캐릭터 숏폼 설계 (오덕이 같은 블로그 캐릭터가 나오는 짧은 영상)

작성 2026-11-15. 레퍼런스: 유튜브 `@gong_gam` '꺼드럭 특'(38초, 조회 74만). 사용자 결정: **메뉴는 숏폼과 분리**, 롱폼(설명 영상)은 대기.

## 0. 레퍼런스 뜯어보기

- 세로 영상, 장면 1~3개(배경 그림은 거의 고정).
- 캐릭터가 화면 아래쪽 절반에 크게. 실제 움직임은 **표정·자세 바뀜 + 살짝 튀기·흔들기 + 확대** 정도(한 장씩 그린 애니메이션 아님).
- 위쪽에 **손글씨풍 굵은 글자**가 단어별로 '팡' 하고 나타남(기울기 약간, 두꺼운 외곽선).
- 아래 자막 2줄 + 낭독(능청스러운 목소리).
- 내용 형식: "○○ 특"(행동 특징 나열), "○○할 때 국룰", 반전 한 방으로 끝.

## 1. 화면 (만들기 → 캐릭터 숏폼, 별도 메뉴)

- 넣는 것: **주제**(예: "아이폰 쓰는 사람 특") + 형식(○○ 특 / 국룰 / 비교 / 자유) + 길이(짧게 20~30초·보통 30~40초·길게 40~55초) + 글꼴 + (선택) 요청사항.
- 캐릭터는 **계정(블로그 폴더)마다 하나**: 이름 + 기준 그림 + 설명 파일. 오덕이 폴더면 `model/basic_oducki.png`, `model/지식파일-오덕이-캐릭터.md`를 쓴다. **코드에 오덕이를 박지 않는다**(블로그 비종속) — 설정 → 캐릭터에서 폴더 안 파일을 고른다.
- 아래 목록: 만든 캐릭터 숏폼(보기·다시 만들기·올렸어요 표시). 숏폼 메뉴의 `ShortBoard`를 그대로 쓴다.

## 2. 핵심 아이디어: 포즈 세트를 한 번 만들어 계속 쓴다

캐릭터를 영상마다 새로 그리면 얼굴이 매번 달라지고 느리다. 그래서:

1. **포즈 세트 만들기(처음 한 번, 사람이 검수)**: 기준 그림을 참고로 표정·자세 그림 약 16장 생성 → 배경 제거 → `<블로그 폴더>\_character\poses\<이름>.png`.
   - 기본 세트: 기본, 말하기(부리 벌림), 웃음, 뻔뻔(꺼드럭), 놀람, 울상, 화남, 생각, 가리키기(좌·우), 엄지척, 점프, 달리기, 들기(소품 자리 빈손), 부끄러움, 졸림.
   - 배경 제거: 단색 배경(초록·자홍 중 캐릭터 색과 먼 것)으로 생성 → 색 빼기(ffmpeg `colorkey` + 가장자리 정리). 흰 털 캐릭터라 흰 배경은 안 됨.
   - 화면에서 포즈마다 미리보기 → 마음에 안 들면 그 포즈만 다시 생성. 승인된 것만 영상에 쓴다.
2. **영상마다**: AI가 대본을 쓰면서 줄마다 포즈 이름 + 움직임 + 효과를 고르고, 배경 그림 1~3장만 새로 생성.

## 3. 대본 형식 (script.json)

```json
{
  "kind": "character",
  "title": ["아이폰 쓰는 사람", "특"],
  "scenes": [{
    "bg_prompt": "Seoul skyline with Namsan tower, flat illustration, no text",
    "beats": [
      { "text": "맥도날드 카페 이케아", "say": "맥도날드, 카페, 이케아 거림", "pose": "smug", "move": "bounce", "fx": ["sparkle"],
        "pop": ["맥도날드!", "카페!", "이케아!"] }
    ]
  }],
  "description": "", "hashtags": []
}
```

- `pose`: 승인된 포즈 이름만. `move`: bounce·shake·pop·zoom·slide·jump·tilt·idle. `fx`: sweat·sparkle·anger·tears·question·heart(CSS·SVG로 그림, 그림 생성 안 함).
- `pop`: 위쪽 손글씨 글자, 낭독 시점에 맞춰 단어별로 나타남(이미지 생성이 아니라 글꼴 — 영상 글자는 움직여야 해서 코드로 얹는다. 썸네일 '코드 글자 금지' 규칙은 정지 썸네일 얘기라 별개).
- 말하는 줄은 `pose`와 `talk` 포즈를 0.15초마다 번갈아 → 입 움직이는 느낌.

## 4. 렌더

- 새 무대 `assets/character.html`: `renderAt(t)` 순수 함수(기존 `stage.html`과 같은 방식, CDP 캡처) — 배경 + 캐릭터 레이어(포즈 이미지, 움직임 곡선) + 효과 + 위 글자 + 아래 자막.
- 낭독: `video.mjs` TTS·톤·음량 맞춤 그대로. 목소리는 능청스러운 남/여 1개씩 골라 기본값.
- 출력: 1080×1920 mp4 + 점검 그림(장면별 한 장).

## 5. 글꼴

- 위 '팡' 글자는 손글씨풍 굵은 글꼴이 필요하다. 후보는 눈누에서 **상업·영상·재배포** 되는 것만(예: 카페24 써라운드는 있음, 손글씨체 1~2종 추가 조사). 넣을 때 `assets/fonts/licenses/README.md`에 기록.

## 6. 롱폼(설명 영상)은 대기

- 이유: 가로 화면 틀·그래프 장면·5분 이상 대본·출처 검증이 모두 새로 필요하고, 방송 화면을 못 써서 그림 품질이 승부. 캐릭터 숏폼의 무대·포즈·TTS가 굳으면 그대로 가로로 넓혀 재사용할 수 있다(오덕이가 진행자).

## 7. 순서

1. 설정 → 캐릭터(기준 그림·설명 파일 고르기) + 포즈 세트 생성·검수 화면
2. `character.html` 무대 + 움직임·효과 + 손글씨 글꼴
3. 대본 프롬프트 + job `character` + 메뉴·목록
4. 실제 한 편 만들어 확인 → 쇼츠 자동화에 형식 추가는 그 뒤
