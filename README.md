# 공방-콘텐츠파일럿

네이버 블로그 글을 백그라운드에서 쓰고 임시저장까지 하는 로컬 관리 페이지(`http://localhost:5999`).

## 실행

`start.cmd`를 더블클릭하면 떠 있던 서버를 끄고, 화면을 새로 빌드(`next build`)한 뒤 서버를 최소화 창으로 띄우고 관리 페이지를 엽니다. 코드를 고친 뒤 다시 시작할 때도 이것만 실행하면 됩니다.
화면(`app/`)을 고친 뒤에는 `npm run build`를 다시 하거나, 개발 중에는 `npm run dev`(핫리로드)로 띄웁니다.

1. 설정 → **계정 관리** → 네이버 계정 추가 → **로그인 창 열기** → 뜬 크롬 창에서 직접 로그인 (계정마다 최초 1회, 세션은 계정별 크롬 프로필 `data/profiles/<계정>`에 남음). 블로그가 여러 개면 계정을 더 추가하고 기본 계정을 정합니다. 인스타·스레드는 지금은 이름·아이디만 적어 둡니다.
2. 설정 → 블로그 작업 폴더(`AGENTS.md`가 있는 폴더)
3. 글 생성하기 → 주제·참고 링크·요청사항·사진/참고 자료 → 백그라운드 작성 → (선택) 임시저장

## 릴스·쇼츠 만들기

메뉴에서 **릴스·쇼츠 만들기**를 선택하고 주제와 영상 형식을 입력합니다. 대본은 선택 사항이며 비우면 Codex가 작성합니다. 이미지·영상은 최대 8개를 직접 넣을 수 있으며, 첨부한 순서대로 장면에 사용합니다. 첨부하지 않으면 Codex가 장면마다 이미지를 생성합니다. 설정된 TTS로 음성을 만든 뒤 자막과 함께 세로 MP4를 합성합니다. 작업 로그에서 진행 상황을 보고, 완료된 영상은 같은 화면 또는 숏폼 만들기 목록에서 미리 볼 수 있습니다. 결과는 기본 블로그 작업 폴더의 `shorts`에 저장됩니다.

주제가 떠오르지 않으면 관심 분야를 입력하고 **AI 주제 추천받기**를 누릅니다. 저장된 핫 키워드와 숏텐츠를 참고하며, 추천 아래에 해당 자료의 수집 시각을 표시합니다. 추천 결과를 누르면 영상 주제에 입력됩니다.

Codex 로그인과 해당 환경의 내장 이미지 생성 도구가 필요합니다. 장면 이미지가 생성되지 않거나 입력한 대본이 변경되면 작업을 실패 처리합니다. 플랫폼 업로드와 발행은 직접 해야 합니다.

## 체험단 정보 조회

**찾기 → 체험단 정보 조회** 또는 `http://localhost:5999/campaigns`에서 블로그 체험단을 검색합니다. 지역·카테고리·유형·사이트·마감으로 좁히고, 마감 임박·최신·경쟁률·모집 인원 순으로 정렬할 수 있습니다. 카드/표 보기를 지원하며, 필터는 주소에, 보기 선택은 브라우저에, 즐겨찾기는 이 PC의 `data/campaigns.json`에 남습니다. 공고를 누르면 원본 사이트가 새 탭으로 열립니다. 신청은 원본에서 직접 합니다.

서버가 켜져 있으면 한국 시간 06~24시에 사이트별 3시간 간격으로 수집합니다. **지금 수집하기**로 수동 실행할 수도 있습니다. 목록 화면은 저장된 데이터만 읽으므로 외부 사이트가 응답하지 않아도 사용할 수 있습니다. **사이트 및 수집 상태**에서 사이트별 수집·켜기/끄기와 최근 이력을 확인합니다. 끄면 해당 사이트 공고를 숨기며, 다시 켜면 복원합니다.

현재 디너의여왕·강남맛집의 공개 목록을 지원합니다. 사이트당 최근 30페이지 이내를 수집하므로 사이트 전체 공고 수와 다릅니다. 서울오빠는 robots.txt, 리뷰노트는 운영정책의 제한에 따라 원본 바로가기를 제공하며, 레뷰도 목록·정책 검증 전까지 원본 바로가기로 제공합니다(2026-11-04 확인). 수집 시 robots와 약관을 다시 확인하고, 403·429 등 접근 제한에는 즉시 중단합니다. 급감이나 수집 실패 시 기존 데이터를 보존하며, 3회 연속 실패하면 기존 Windows 알림을 사용합니다.

수집기·조회는 `campaigns.mjs`, 화면은 `app/campaigns.jsx`, 자체 검사는 `campaigns.check.mjs`입니다. 추가 서버나 DB, 설치 패키지는 필요하지 않습니다.

## 구조

| 파일 | 역할 |
|---|---|
| `server.mjs` | 5999 포트. `/api`는 직접 처리하고 나머지는 Next로 넘김. 작업 큐(`data/jobs.json`), 로그(`data/logs`) |
| `app/` | 관리 화면 (Next.js + React) |
| `ai.mjs` | `codex exec` / `claude -p` 실행. 프롬프트는 stdin으로, 대화 기록은 남기지 않음 |
| `naver.mjs` | 전용 크롬 프로필(headless): 세션 확인, 화면 수집, 에디터 주입, 임시저장 |
| `video.mjs` | 숏폼 렌더러: 대본(script.json) → 문장별 감정 TTS(Edge 무료 / ElevenLabs / Google) → 무대 프레임 캡처 → ffmpeg 합성. 결과는 `<블로그 폴더>/shorts/` |
| `shortents.mjs` | 숏텐츠 수집: 검색창 숏텐츠(로그인 없는 JSON, 20개) + 분류별 숏텐츠(검색 결과 HTML, 10분류×5개). 서버가 30분마다 받아 `data/shortents.json`에 쌓음 |
| `assets/stage.html` | 숏폼 무대: 시간 t의 화면을 그리는 HTML/CSS (전환·키프레임 줌·흔들기·글리치·스티커·단어 강조 자막·이글이글 글씨) |
| `assets/fonts/` | 영상용 OFL 폰트: 검은고딕·도현·주아(제목), Pretendard(자막) |
| `vendor/` | Naver-Blog-Helper-Extension의 `html.js`(HTML→에디터 문서모델), `driver.js`(이미지 업로드·적용) 복사본 |

글은 블로그 폴더의 `AGENTS.md` 규칙대로 AI가 직접 씁니다. 그래서 다른 블로그도 폴더만 바꾸면 그 블로그 규칙대로 씁니다.
AI 명령은 `config.json`의 `engines`에서 바꿉니다. codex는 `npm i -g @openai/codex`로 설치합니다.

기본값은 이 PC에서만 접속합니다. 같은 네트워크의 휴대폰·다른 PC에서도 쓰려면 `config.json`의 `lanHost`에 서버 PC의 IPv4 주소를 넣고 서버를 다시 실행합니다. 현재 PC는 `192.168.10.122`로 설정되어 있으며, `http://192.168.10.122:5999`로 접속할 수 있습니다. Windows 방화벽에서 이 주소의 TCP 5999 포트를 같은 네트워크에 허용해야 합니다. `lanHost`를 비우면 다시 로컬 전용으로 실행합니다.

로컬 주소와 지정한 LAN IP만 허용하며, Host·Origin 검사와 쓰기 요청의 `x-bh: 1` 헤더 검사를 유지합니다. 네트워크 설정 변경은 서버를 다시 실행해야 반영됩니다.

## 블로그 폴더 구조 (다른 블로그에서 쓰기)

분류는 정해 두지 않고 블로그 폴더에서 찾습니다. `meta.json`이 든 폴더가 글 하나이고, 그 글을 담은 상위 폴더 이름이 분류입니다.

```text
<블로그 폴더>\
├─ AGENTS.md            (선택) 작성 규칙. 없으면 기본 형식으로 씁니다
├─ 맛집\20261016-주제\  → 분류 "맛집"
│   ├─ 주제.html, meta.json, assets\
└─ 20261016-주제\       → 분류 없음
```

분류 이름은 글 `meta.json`의 `category_name`(가장 많이 쓰인 값), 없으면 폴더 이름입니다.
`shorts`·`tmp`·`output`·`assets`·`docs`·`model`·`sticker`와 `_`·`.`로 시작하는 폴더는 글로 보지 않습니다.
